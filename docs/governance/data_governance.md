## 3. Data Classification Scheme

All data processed or generated by the platform is assigned one of three confidentiality and integrity classifications:

### 3.1 Class A: Public Open Data
- **Artifacts**: Disseminated CAP XML warnings, public web map layers, aggregated storm statistics, and post-event case studies.
- **Access**: Open to public, municipal authorities, research institutions, and disaster agencies.
- **Integrity**: Signed with public digital certificate to prevent spoofing.

### 3.2 Class B: Operational Telemetry & System Logs
- **Artifacts**: Machine learning training tensors, intermediate normalized feature grids (`.npy`), model performance metrics, server CPU/memory telemetry.
- **Access**: Restricted to operational duty meteorologists, data engineers, and platform administrators.
- **Retention**: Rolling 90-day retention on local storage; compressed cold storage for 1 year.

### 3.3 Class C: Restricted & Forensically Sensitive
- **Artifacts**: Production database (`data/aerocast.sqlite3`), operator audit log (`audit_log` table), forecaster digital credentials, administrative API tokens, and hardware siren control endpoints.
- **Access**: Strictly restricted to authenticated personnel with `ADMIN` or `LEAD_MET` role.
- **Retention**: 7-year immutable retention. Deletion prohibited by automated pruning daemons.

## 4. Ingestion Quality Control (QC) & Validation Protocols

Before any raw observational file or stream is ingested into the analytical pipeline, it must pass three automated validation gates:

### 4.1 Gate 1: Checksum & Timestamp Deduplication
- Every ingested file is hashed via SHA-256 upon receipt.
- The hash is compared against the `raw_ingest_log` table. Duplicate transmissions are discarded immediately with HTTP 200/ACK without re-processing.

### 4.2 Gate 2: Physical Plausibility & Numerical Range Checks
Tensors are passed to `NumericalSafetyValidator`:
- **Reflectivity ($Z$)**: Must satisfy $-32.0\text{ dBZ} \le Z \le +95.0\text{ dBZ}$. Values $> 75\text{ dBZ}$ are flagged for hail review; values $> 95\text{ dBZ}$ are rejected as unphysical.
- **Brightness Temperature ($T_B$)**: Must satisfy $170.0\text{ K} \le T_B \le 340.0\text{ K}$.
- **Lightning Flash Density**: Must satisfy $\ge 0\text{ flashes/km}^2/\text{min}$.
- **NaN / Inf Check**: If a tensor contains even a single `NaN` or `Inf` value, the frame is rejected, quarantined, and replaced with persistence decay.

### 4.3 Gate 3: Spatial Resampling & Grid Registration
- All spatial inputs are projected and bilinearly resampled onto the standardized regional grid:
  - Spatial Extent: $12.0^\circ\text{N}$ to $14.5^\circ\text{N}$, $79.0^\circ\text{E}$ to $81.5^\circ\text{E}$ (Centered over Chennai Metropolitan Region).
  - Grid Dimensions: $64 \times 64$ pixels.
  - Nominal Pixel Resolution: $\approx 4.3\text{ km} \times 4.3\text{ km}$.
  - Temporal Cadence: Standardized 15-minute time steps ($:00, :15, :30, :45$).

```
+------------------------------------------------------------------------------------+
|                                DATA LIFECYCLE TIERS                                |
+------------------------------------------------------------------------------------+
|                                                                                    |
|  [ Ingested Raw Scans ] ---> Hot Tier (Fast NVMe SSD)      : 30 Days               |
|                                |                                                   |
|                                v                                                   |
|  [ Severe Weather Events ]-> Warm Tier (Compressed Disk)   : 1 Year                |
|                                |                                                   |
|                                v                                                   |
|  [ Audit Logs & Warnings ]-> Cold Vault (Immutable Backup) : 7 Years (Legal Hold)  |
|                                                                                    |
+------------------------------------------------------------------------------------+
```

### 5.1 Automated Pruning Rules
- A nightly maintenance cron (`02:00 IST`) executes `scripts/prune_data.py`:
  - Deletes raw radar scans in `data/raw/` older than 30 days, unless flagged as part of an archived case study.
  - Clears temporary cache files in `data/cache/` older than 24 hours.
  - Executes SQLite `VACUUM` and `PRAGMA optimize` on the first Sunday of every month.
