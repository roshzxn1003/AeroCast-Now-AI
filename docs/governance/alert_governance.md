## 1. Scope & Objective

This policy defines the meteorological criteria, data standards, deduplication logic, rate limiting, and governance workflows governing the generation, clearance, and dissemination of severe weather alerts emitted by the **AeroCast-Now AI** platform.

The goal is to ensure that all alerts delivered to disaster management authorities (NDMA, SDMA), meteorological agencies (IMD), civil protection networks, and the public are:
1. **Accurate and Cross-Validated**: Grounded in multi-sensor agreement (Radar + Lightning + Satellite).
2. **Standard-Compliant**: Fully formatted in Common Alerting Protocol (CAP v1.2).
3. **Actionable & Non-Spammy**: Controlled by spatial deduplication to prevent alert fatigue.
4. **Legally and Operationally Auditable**: Signed and tracked in tamper-evident storage.

## 2. Common Alerting Protocol (CAP v1.2) Specification

All external alerts generated by AeroCast-Now AI are formatted in compliance with the **OASIS Common Alerting Protocol Version 1.2**.

### 2.1 Core CAP Header Mapping

| CAP Element | System Mapping | Description / Permitted Values |
|:---|:---|:---|
| `<identifier>` | `AEROCAST-<YYYYMMDD>-<UUID>` | Universally unique alert identifier. |
| `<sender>` | `aerocast-ops@imd.gov.in` | Authenticated system or forecaster mailbox. |
| `<sent>` | ISO 8601 UTC Timestamp | Exact UTC time the alert was signed and cleared. |
| `<status>` | `Actual` \| `Test` \| `Draft` | Production alerts must always be `Actual`. Drills must use `Test`. |
| `<msgType>` | `Alert` \| `Update` \| `Cancel` | Lifecycle state of the message. |
| `<scope>` | `Public` \| `Restricted` | Target dissemination scope. |

## 3. Convective Trigger Thresholds & Classification Matrix

Alerts are categorized into three severity levels according to physical atmospheric thresholds measured across multi-sensor inputs:

```
+---------------------------------------------------------------------------------------+
|                            CONVECTIVE THRESHOLD MATRIX                                |
+------------+-------------+----------------+---------------+------------+--------------+
| Alert Tier | Radar (dBZ) | Lightning Jump | Cloud Top TB  | VIL (kg/m²)| Action       |
+------------+-------------+----------------+---------------+------------+--------------+
| YELLOW     | 30 - 40 dBZ | None (< 5/min) | 230K - 250K   | 5 - 15     | Forecaster   |
| (Advisory) | Light/Mod TS| Steady rate    | Developing    | Moderate   | Queue Log    |
+------------+-------------+----------------+---------------+------------+--------------+
| ORANGE     | 40 - 50 dBZ | 2-sigma Jump   | < 220 K       | 15 - 30    | Forecaster   |
| (Warning)  | Severe Cell | (10 - 25 /min) | Overshooting  | High       | Sign-off Req |
+------------+-------------+----------------+---------------+------------+--------------+
| RED        | >= 50 dBZ   | Severe Surge   | < 205 K       | > 30       | Dual-Key Met |
| (Emergency)| Extreme/Hail| (>= 30 /min)   | Deep Convect  | Severe     | + Siren Auth |
+------------+-------------+----------------+---------------+------------+--------------+
```

### 3.1 Lightning Jump Validation Gating
A raw lightning surge detected by the TOA detector **cannot** independently trigger an ORANGE or RED alert unless confirmed by radar reflectivity and Vertically Integrated Liquid:
- **Mandatory Gating Rule**: If lightning jump algorithm reports a 2-sigma surge, the system queries the collocated radar grid within a $10\text{ km}$ radius. If radar reflectivity is $< 35\text{ dBZ}$ and VIL is $< 15\text{ kg/m}^2$, the jump is classified as a **Potential RF Interference Spike** and downgraded to Advisory status pending human inspection.

## 4. Deduplication, Rate Limiting & Alert Suppression

### 4.1 Spatio-Temporal Deduplication (20-Minute Window)
- **Problem**: In a convective nowcast cycle updating every 5 to 15 minutes, a moving thunderstorm cell can trigger repeated identical alerts for the same geographic district, causing alarm fatigue and public desensitization.
- **Rule**: Once an alert has been issued for a designated area polygon:
  1. No new alert of the **same or lower severity** may be issued for an intersecting polygon within **20 minutes**.
  2. If the cell severity **escalates** (e.g., from ORANGE to RED), an immediate CAP `Update` message is permitted.
  3. If the cell moves into an adjacent previously unwarned sector, a new alert is issued solely for the newly affected polygon.

### 4.2 Clear-Air Clutter Suppression
- Radar echoes with reflectivity between $15\text{--}25\text{ dBZ}$ that exhibit zero Doppler velocity variance, zero cloud-top cooling on INSAT-3D, and zero lightning activity are classified as **Anomalous Propagation (AP) / Sea Clutter**.
- The rule engine automatically suppresses alert generation on these clutter masks.

### 4.3 Explicit Alert Cancellation (CAP `Cancel`)
- When a tracked convective cell diminishes below $30\text{ dBZ}$, lightning ceases for 15 consecutive minutes, or the cell exits the regional warning boundary:
  - The system generates a CAP message with `<msgType>Cancel</msgType>` referencing the original `<identifier>`.
  - Dissemination channels notify the dashboard that the hazard has ended.

```

+------------+      +------------+      +------------+      +------------+      +------------+
| NDMA / CAP |      | Operational|      | Municipal  |      | Disaster   |      | State Met  |
| Webhook    |      | Dashboard  |      | Siren Relay|      | SMS / Push |      | Public RSS |
| Gateway    |      | WebSocket  |      | Controller |      | Gateway    |      | Feed       |
+------------+      +------------+      +------------+      +------------+      +------------+
 (X.1303 Push)       (Real-Time)        (Dual-Key)          (Bulk Telco)        (Public Web)
```

1. **NDMA / SDMA National Warning Portal**: Pushed via authenticated HTTPS Webhook adhering to the National Disaster Management Authority CAP format.
2. **Operational Duty Dashboard**: Broadcast instantaneously over authenticated WebSocket (`/api/ws/alerts`) to all duty consoles.
3. **Municipal Siren Relay Gateway**: Hardware relay controllers at coastal sirens and airfield towers. Activation requires dual-key cryptographic signature.
4. **Disaster SMS Gateway**: Automated distribution to registered emergency relief commissioners and district collectors.

## 6. False Alarm Governance & Incident Reporting

1. **False Alarm Definition**: An alert is classified as a False Alarm if an ORANGE or RED alert was issued, but surface observations, automated weather stations (AWS), and post-event radar verification confirm zero lightning strikes, wind gusts $< 35\text{ km/h}$, and rainfall $< 5\text{ mm}$ within the warning polygon.
2. **Review Window**: Every morning at 09:00 IST, the shift lead conducts a post-event review of all alerts issued in the preceding 24 hours.
3. **FAR Incident Log**: If the monthly False Alarm Ratio ($FAR$) exceeds $0.35$, an automatic governance audit is triggered. Model retraining datasets and radar calibration matrices are audited for systematic bias.
